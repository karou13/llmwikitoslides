# 研究模型與資料簡報：流程規格

## 🎯 目標

只用 `wiki/` 的內容，產出 10–12 頁的 `presentation/research-model/deck.html`，讓不熟悉主題的人看懂：

1. **我們要做什麼**：研究題目、研究定位（國家異質性）、研究問題、H1–H3。
2. **怎麼做**：資料（變數、來源、樣本國家、期間）與模型（H1、H2、H3、穩健性檢驗）。
3. **為什麼這樣做**：每個設計選擇的文獻先例，以及哪些是本研究的延伸。

## 🗺️ 流程圖

```
[0] 研究總覽 ──→ 👤 人工確認研究設計（寫入 wiki/research-overview.md）
        │
[1] 檢索 wiki ──→ ✅ 覆蓋率關卡
        │              └─ 不足 → 停下，回報缺什麼
[2] 證據卡（每篇一張，平行）──→ ✅ 卡片檢查
        │              └─ 錯 → 只重抽那一張
[3] 大綱 ──→ 👤 人工確認大綱
        │              └─ 退回 → 修大綱，或回 [1] 補檢索
[4] 逐頁稿（每頁內部最多修 2 輪）──→ ✅ 程式檢查 ＋ 🧑‍⚖️ 獨立 AI 審查
        │              └─ 錯 → 只修出錯的那頁
[5] 渲染 HTML ──→ ✅ 渲染檢查
        │              └─ 字太多 → 退回 [4] 縮短那頁
[6] 交件：deck.html ＋ report.md
```

👤 = 人工確認，未經確認不得進入下一步。✅ = 檢查關卡。

## 每一關：只能看什麼、產出什麼、不能做什麼

| 節點 | 只能看 | 產出 | 不能做 |
|---|---|---|---|
| [0] 研究總覽 | 使用者提供的研究設計、wiki | `wiki/research-overview.md` 草稿 | 未經使用者確認就寫入；替使用者決定「待確認」項目 |
| [1] 檢索 | `wiki/index.md` 及其列出的頁面 | `sources.md`：要用的 wiki 頁面清單與用途 | 使用 wiki 以外的資料 |
| [2] 證據卡 | **一篇**來源筆記（或一頁綜合頁） | `cards/<來源檔名>.md`：該篇與本研究相關的模型、資料、結果、頁碼 | 混入其他來源的內容 |
| [3] 大綱 | `research-overview.md`、所有卡片 | `outline.md`：每頁標題、要講的重點、引用哪些卡片 | 引用不存在的卡片 |
| [4] 逐頁稿 | 已確認的大綱＋該頁對應的卡片 | `drafts/slide-NN.html` | 寫入卡片以外的內容 |
| [5] 渲染 | 已通過檢查的逐頁稿 | `deck.html` | 修改任何一個字（只調版面） |
| 檢查關卡 | 成品＋引用的 wiki 頁面 | `report.md` 的檢查紀錄 | 自己動手改成品 |

## 狀態檔案

```
presentation/research-model/
├── sources.md           # [1] 檢索結果
├── cards/               # [2] 證據卡，一篇一張
├── outline.md           # [3] 大綱（使用者確認後才往下）
├── drafts/              # [4] 逐頁稿
├── deck.html            # [5] 成品
├── report.md            # 所有檢查與退回紀錄
└── review-round-N.md    # 第 N 輪 AI 審查原始意見
```

每一關的產出都能打開看、單獨重跑。

## ✅ 各關卡的檢查內容

### 覆蓋率關卡（[1] 之後）
- `research-overview.md` 的研究問題、研究假設、資料與資料來源、研究模型四節都有內容，不是「待整理」。
- 可引用的來源筆記至少 3 篇。
- 「做什麼、怎麼做、為什麼」三部分各至少有一個 wiki 頁面可引用。
- 研究總覽中每個模型設定，都能在 wiki 找到「文獻先例（哪一篇）」或明確標為「本研究延伸」（2026-11-24 加入，見下方「修改紀錄」）。

任一不符 → 停下，回報缺什麼，不產出簡報。

### 卡片檢查（[2] 之後）
- 卡片上的每個數字、頁碼都能在該篇來源筆記中找到。
- 卡片標明該篇是「文獻先例」的哪一部分（資料、AI 指標、模型、結果）。

### 程式檢查＋獨立 AI 審查（[4] 之後）

程式檢查：

```
python -I .claude/skills/research-model-deck/check_deck.py presentation/research-model/deck.html
```

（逐頁稿階段可先把 drafts 組成暫時的 deck 再檢查。）檢查項目：
1. 頁數 10–12（腳本預設 8–15，以本規格為準）。
2. 每頁至少一個 `<cite data-wiki="wiki/….md">`。
3. 被引用的 wiki 頁面存在。
4. 頁面上的數字（年份、小數、百分比）能在該頁引用的 wiki 頁面中找到。

獨立 AI 審查：開一個**新的 subagent**（不帶本對話脈絡），只給它簡報與引用的 wiki 頁面，逐頁檢查並寫入 `review-round-N.md`：
- **忠實度**：
  - 敘述是否與引用頁一致。
  - 有沒有把相關寫成因果、把 AI 專利寫成企業採用率、把模擬寫成實證、把「待確認」寫成已確定。
- **覆蓋率**：研究總覽的每個假設、變數、模型是否都有出現；「做什麼、怎麼做、為什麼」是否齊全。
- **可理解性**：沒有背景的人能否看懂每個公式符號。

審查只回報問題，不修改簡報。

### 渲染檢查（[5] 之後）

用內建瀏覽器開啟 `deck.html`，執行：

```js
[...document.querySelectorAll('section.slide')].map((s,i)=>({page:i+1, overflow: s.scrollHeight > s.clientHeight + 1 || s.scrollWidth > s.clientWidth + 1})).filter(x=>x.overflow)
```

回傳空陣列，且截圖目視沒有文字被裁切，才算通過。

## 內容規則

- **AI 指標：** AI 專利與出版物衡量 AI 創新活動，不得寫成企業 AI 採用率（`wiki/topics/synthesis/ai-measures.md`）。
- **結果的性質：** 文獻結果寫成相關，不寫成因果；模擬結果要標明是模擬值。
- **先例或延伸：** 每個模型設定都要標「文獻先例（哪一篇）」或「本研究延伸」（依 `wiki/research-overview.md` 與 `wiki/topics/synthesis/methods-data-structures.md`）。
- **待確認事項：** `research-overview.md` 中標「待確認」的項目，簡報上照樣標示。
- **轉引文獻：** wiki 中沒有來源筆記、只出現在其他文獻引述中的研究，寫成「某篇引述」。

## HTML 標記約定

- 每頁一個 `<section class="slide">`，固定 16:9（`width:1280px; height:720px; overflow:hidden`）。
- 每頁至少一個 `<cite data-wiki="wiki/相對路徑.md">顯示文字</cite>`。

## 🔁 退回規則

錯在哪一關，就退回哪一關；其他頁面不動。

| 問題 | 退回到 |
|---|---|
| 某頁講錯 | [4] 只修那一頁 |
| 卡片本身錯 | [2] 重抽那一張卡，再重寫引用它的頁面 |
| 字太多、溢出 | [4] 縮短那一頁，不硬塞 |
| 使用者看大綱時發現缺主題 | [1] 補檢索 → [2] 補卡 → [3] 修大綱 |
| 研究設計本身要改 | [0] 改研究總覽，經使用者確認後重跑 |

每一輪只修 `report.md` 本輪列出的問題。

## 🛑 停止條件

- 覆蓋率關卡不通過 → 一開始就停，回報缺什麼。
- 程式檢查、AI 審查、渲染檢查全部通過 → 交件，附 `report.md`。
- [4]→[5] 的修正改滿 3 輪仍有問題 → 停止，交出目前版本，在 `report.md` 列出未解決的問題，交由使用者決定。
